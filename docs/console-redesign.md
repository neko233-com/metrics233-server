# Console layout and display conventions

The row-based 0.2.21 design below is retained as historical acceptance. The current GitHub Dark card directory,
network view and final 0.2.24 comparison are specified in [instance-directory.md](instance-directory.md).

The service directory uses one aligned list with environment section labels, a compact search/sort toolbar and persistent selection controls. Friendly service titles do not replace the canonical identity. The directory never invents CPU, memory or health values from report labels. Each native page remains bounded to 50 instances; environment counts/filters and ordering explicitly describe that page. Search still covers all identities through the server API. Default service-number ordering avoids polling-driven row movement; recent-report ordering is opt-in.

Instance details put the service identity, section navigation and time range above physical-host, service-process and business metrics. Host association and template management stay behind Dashboard settings. Existing independent/inherited templates, SQL multi-sort and virtual player-region lists remain functional. Embedded host history, disk inventory and alert policy are expandable so the three current instruments remain the first resource view; expanding history starts its bounded queries. One size control applies to all sections.

The visual system uses a dark blue-gray canvas, restrained cyan accents, fine separators, 14px controls, readable service names, 8/12/16/24px spacing and a responsive list that stacks metadata on small screens. Semantic green/amber report dots describe freshness only. No decorative gradients, illustrations or extra KPI tiles are needed.

Capacity displays use decimal B/KB/MB/GB (1000-based). API/storage units remain bytes. Complete human-readable timestamps use `yyyy-MM-dd HH:mm:ss` in the browser computer's local timezone; the top bar shows its current GMT offset. Transport ISO timestamps and query timezone/date-math semantics remain unchanged. Chart axes can split the same timestamp over two lines for readability. Data-point timestamps belong in metric details; current-value panels must still disclose stale results instead of claiming historical samples are current.

Design references were generated for the directory and selected-instance view before implementation. Intentional functional differences: no inert view-mode control, no invented total page count, stable service-number default sort, real query-driven panels and the user's requested absolute time format. Acceptance requires the actual Edge list → filter/search → selected instance → resource/SQL flow, responsive layout, console checks and a concept/render comparison. Source/build success alone does not establish that acceptance.

Current business defaults and process projections enforce a 90-second source-sample freshness window. A newly evaluated PromQL response timestamp must not revive an old source value. Explicit historical ranges keep their historical meaning; valid zero samples remain visible. Capacity pressure uses total minus available space and therefore includes filesystem reserved space. Expanding a cloud volume alone does not expand its partition or filesystem.

The concept/render review checks five concrete points: sidebar/main proportions; dark canvas and restrained cyan selection; title/search/filter hierarchy; aligned 68px service rows with secondary identity/IP details; and the selected-instance progression from identity through resource instruments to process/business data. Local Edge acceptance uses 1586×992 and 390×844. Fixture values are synthetic and cannot establish live collection. Above-fold copy changes intentionally clarify current resource definitions, retained pagination semantics and absolute report times. Existing brand/navigation icons and actual five process statistics are preserved instead of copying illustrative mockup icons or omitting real panels.

Edge separately verified real game/gateway reports, physical-host instruments, MB displays, browser-local current clock, the recent-hour history/SQL views and responsive rendering. The direct concept/render comparison found no remaining material layout mismatch; the functional differences described above are intentional.
