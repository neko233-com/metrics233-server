# 告警持续时间、恢复和通知冷却

CPU/磁盘持续高并不需要每次评估都发消息。默认通知只在进入告警和恢复时发送；相同活动周期内的 `Firing/Recovering/NoData/Error` 切换不会反复创建通知。只有显式配置 `repeat_interval > 0` 才有周期提醒，空值或 `0s` 表示关闭。

## 不同时间字段的职责

| 字段 | 作用 | 默认/范围 |
| --- | --- | --- |
| 规则 `for_seconds` | 条件连续满足多久才进入 Firing，短尖峰不告警 | API 默认 0；0–604800 秒 |
| 规则 `keep_firing_for_seconds` | 条件恢复后保留 Recovering，连续正常满时长才发恢复 | API 默认 0；0–604800 秒 |
| 规则 `notification_cooldown_seconds` | 同接收者、规则、实例、severity 的所有成功 firing 通知最低间隔，含同周期提醒和恢复后重触发 | 新建 UI 默认 3600 秒；旧规则/省略字段为 0（关闭）；0–604800 秒 |
| 策略 `group_wait` | 首批分组通知的聚合等待 | 仅显式配置时启用分组 |
| 策略 `group_interval` | 已发送分组的成员/状态变化，至少间隔多久再发 | 配置时必须大于 0 |
| 策略 `repeat_interval` | 相同活动周期的定期提醒 | 默认关闭；若需长期提醒可显式设 `4h`；按 group_interval 向上取整 |

资源告警可从“持续 5 分钟触发、连续正常 5 分钟恢复、通知冷却 1 小时”起步，再按实际业务调整。不要自动套用到所有业务阈值。需要持续提醒时单独配置 repeat；相同周期实际重复间隔至少为 `max(rule CD, policy repeat)`，短 repeat 不能绕过较长 CD。repeat 为 0 时仍关闭周期提醒，CD 不会自行创建提醒。

## 冷却语义

原生规则创建/更新 API 为 `POST /api/v1/alerts/rules` 和 `PUT /api/v1/alerts/rules/{uid}`，添加整数 `notification_cooldown_seconds`，更新仍须带最近的 `version`。非法范围返回 400；GET 返回相同值。

- 冷却从**最近一次成功的 firing ACK**起算，保存在 SQLite，和队列的 sent 状态同事务提交。发送失败、HTTP 超时、飞书错误业务码或恢复消息都不会推进这个时间。
- 首次告警、新接收者、不同实例立即发送。实例身份包含有效标签；severity 升级为新的实例，旧严重级别的 ACK 不会阻塞它。不同资源的首次告警不会共用全局冷却。
- 例如 10:00 成功告警、10:10 恢复、10:20 再触发，CD 为 1 小时：恢复通知正常发送，新 firing 最早 11:00 发送。等待期间保留告警状态和触发周期快照，不改变指标存储或评估；发送前再次检查这个周期仍活跃。
- 如果等待中的周期提前恢复，取消待发 firing。没有成功送达 firing 的周期不会发送孤立恢复。已经发出的网络请求无法撤回；超时后的实际接收情况仍以明确 ACK 为准。
- 失败重试沿用原通知 ID、正文、尝试次数和退避，不因 CD 另等一小时；本轮成功之后才建立/推进锚点。恢复通知和测试通知不受 firing 冷却。
- 规则编辑、暂停/再启、联系点停用/启用、进程重启不会清空 ACK 锚点。真正删除规则或联系点会清理其元数据；把 CD 改为 0 是显式关闭，而不是重置评估时意外绕过。
- 分组按成员独立筛选冷却，未送达成员不产生恢复；其他新实例仍能进入分组，已经冷却中的旧成员不会被顺带再次发送。相同周期显式 repeat 遵守 CD 最低间隔和更长的策略 repeat；只有 CD 为 0 才完全保持旧重复时序。静默结束后的恢复提醒也遵守 CD，真正恢复通知不被该 firing 截止时间拖延。

ACK 元数据与普通通知历史独立。最长 CD 为 7 天，过期锚点可回收；仍活跃或正在等待恢复的周期保留单独的成功回执，防止普通 outbox 历史清理造成恢复丢失。完成恢复或删除资源会清理对应回执。

## 验证边界

`TestNotificationCooldown*` 通过实际本地 HTTP 接收端分别覆盖分组/非分组：恢复后冷却、跨重启、冷却期提前恢复、首次未送达取消、失败按原 ID 重试、新实例/接收者/severity、暂停编辑和联系点停启不重置、历史清理后恢复，以及静默恢复提醒。`repeat=10s/CD=300s` 在 10、299 秒不发送，到 300 秒发送；`CD=0` 仍在 10 秒重复；`repeat=4h/CD=1h` 不会提前到 1 小时；repeat 为 0 的新成员变动不生成隐式提醒。首次提醒的 503 仍按原 ID 在 5 秒后重试，成功之后才推进 CD。原生 API 覆盖 0、3600、604800 的保存读取和越界拒绝。确定性测试使用传入的评估/调度时间，不需要睡眠一小时。

这些是本地运行与持久化证据；不代表已有线上资源规则采用了推荐值。生产策略更新、真实外部通知和新版本部署由操作者单独验收。
